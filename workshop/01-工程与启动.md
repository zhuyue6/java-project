## 讲解

### 1. 这个仓库里有两个 Maven 工程

Maven 在这里相当于前端的包管理加构建脚本。一个模块用一份 `pom.xml` 描述「我是谁、依赖谁、怎么编译」。

根目录 `pom.xml`：

- `packaging` 为 `pom`，它自己不产出可运行的服务，只当父工程。
- `<modules>` 里挂着 `clock-my-goal`。在根目录执行 `mvn clean package` 时，Maven 会顺着模块列表去编子项目。
- `properties` 把编译版本固定为 JDK 17，源码编码是 UTF-8。
- `parent` 指向 `spring-boot-starter-parent` 3.2.0。子模块写依赖时往往只写名字，版本由这个父工程统一管理。这和前端 monorepo 里根包锁定依赖版本是同一类做法。

`clock-my-goal/pom.xml` 才是打卡应用：

- 它的 `parent` 指回根工程 `com.zhuyue:apps:1.0.0-SNAPSHOT`。
- `packaging` 为 `jar`。Spring Boot 插件会打出一个带依赖的可执行 jar，主类是 `com.zhuyue.clockMyGoal.Application`。
- 和本课相关的依赖：

| 依赖 | 在项目里的角色 |
| --- | --- |
| `spring-boot-starter-web` | 接收 HTTP，把 Java 对象写成 JSON |
| `spring-boot-starter-validation` | 按 DTO 上的注解校验入参 |
| `mybatis-spring-boot-starter` + `mysql-connector-j` | 用 Mapper 接口执行 SQL |
| `spring-boot-starter-data-redis` | 登录黑名单、用户状态缓存 |
| `jjwt-api` / `jjwt-impl` / `jjwt-jackson` | 签发和解析 JWT |
| `lombok` | 编译期生成 getter、setter、builder，源码里看到 `@Data` 就有这一套方法 |

`java-workbook` 在父 POM 里被注释掉了，是单独的语法练习，这门课不讲。

### 2. 源码目录怎么读

业务代码都在：

```text
clock-my-goal/src/main/java/com/zhuyue/clockMyGoal/
  Application.java          启动类
  common/                   所有模块共用：鉴权、异常、响应包装、配置
  modules/
    auth/                   注册、登录、登出
    user/                   用户资料、列表、头像
    goal/                   打卡目标
    label/                  标签
    admin/                  管理端
```

每个业务模块固定这些包：

```text
controller      接 HTTP
service         业务接口
service/impl    业务实现
mapper          数据库接口
entity          和表字段对应的对象
dto/request     HTTP 入参
dto/response    返回给前端的对象
```

资源文件在 `clock-my-goal/src/main/resources/`：

- `application.yaml`：端口、数据源、Redis、JWT、MyBatis、日志。
- `mapper/*.xml`：SQL。Java 接口只有方法名，SQL 写在 XML 里。

`docker/` 是运行依赖：MySQL、Redis、Nginx、应用容器的编排。

打开任意一个类，先看第一行 `package`。包名能直接告诉你它是入口、共用设施，还是某个业务的某一层。

### 3. 进程从 Application 开始

```10:14:clock-my-goal/src/main/java/com/zhuyue/clockMyGoal/Application.java
@SpringBootApplication
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
```

`@SpringBootApplication` 做三件事：把这个类标成配置、按它所在的包扫描组件、按 classpath 里的依赖做自动配置。扫描起点是 `com.zhuyue.clockMyGoal`，所以 `modules` 和 `common` 下带 `@RestController`、`@Service`、`@Mapper` 的类会被装进容器。后面课里说的「注入」，就是从这只容器里取已经创建好的对象。

本地开发可以在 IDE 里运行这个 `main`。端口默认来自配置里的 `server.port`。

### 4. 配置文件只声明占位，值在运行时注入

`application.yaml` 里和启动相关的几段：

```yaml
server:
  port: ${SERVER_PORT:9090}

spring:
  datasource:
    url: ${DB_URL}
    username: root
    password: ${DB_PASSWORD}
  data:
    redis:
      host: ${REDIS_HOST:127.0.0.1}
      port: ${REDIS_PORT:6379}
      password: ${REDIS_PASSWORD:123456}
```

`${SERVER_PORT:9090}` 的意思是：环境变量 `SERVER_PORT` 有值就用它，没有就用 `9090`。`${DB_URL}` 没有冒号默认值，环境里没配这个变量时，数据源起不来。

Docker Compose 里 `clock-my-goal` 服务的 `environment` 就是在给这些占位赋值。容器之间用服务名互通：`DB_URL` 指向 `mysql:3306`，`REDIS_HOST` 是 `redis`。本机 IDE 直接跑 `Application` 时，要自己准备同样的环境变量，并让 MySQL、Redis 的端口映射到本机。

JWT、微信小程序的 `WX_APPID` / `WX_SECRET` 也是同一套写法。密钥放在环境变量里，源码和 yaml 只保留名字。

MyBatis 这段先记住，第 5 课展开：

```yaml
mybatis:
  mapper-locations: classpath:mapper/*.xml
  configuration:
    map-underscore-to-camel-case: true
```

它把 `resources/mapper/` 下的 XML 登记为 SQL，并把数据库列 `user_name` 填进 Java 字段 `userName`。

### 5. 库和表在第一次启动 MySQL 时建好

`docker-compose.yaml` 把 `./mysql/init` 挂到容器的 `/docker-entrypoint-initdb.d`。MySQL 官方镜像约定：数据目录还是空的时候，会执行这个目录里的 SQL。卷里已经有数据时，脚本不会再跑。

`init.sql` 建立库 `clock_my_goal` 和四张表：

| 表 | 存什么 |
| --- | --- |
| `user` | C 端用户。`user_name` 唯一，`status` 0 停用、1 正常 |
| `goal` | 某个用户的打卡目标，带周期、次数、到期时间 |
| `goal_label` | 标签。名称加类型，在业务里按用户去重 |
| `admin_user` | 管理端账号。脚本末尾插入了一条初始管理员 |

表字段用下划线，Java 实体用驼峰。两边的对应关系交给第 5 课的 MyBatis 配置。

初始管理员的用户名和密码写在 `init.sql` 最后一条 `INSERT` 里，密码以明文落库。第 6 课会看到登录就是用这串字符做比对。

### 6. 本地把依赖容器拉起来

在 `clock-my-goal/docker` 目录：

```sh
docker compose up -d mysql redis
```

看状态：

```sh
docker compose ps
docker compose logs -f mysql
```

`mysql`、`redis` 都带了 healthcheck。应用容器要等它们健康之后才启动；本课如果只在 IDE 里跑 Java，至少要确认这两个容器是 healthy，并且本机的 `3306`、`6379` 能连上。

编译业务模块（在仓库根目录）：

```sh
mvn -pl clock-my-goal -am clean package -DskipTests
```

`-pl clock-my-goal` 只构建这个模块，`-am` 会带上它的父工程。产物在 `clock-my-goal/target/`。

IDE 运行前需要的环境变量，名字与 `docker-compose.yaml` 里 `clock-my-goal.environment` 一致：`DB_URL`、`DB_PASSWORD`、`REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD`、`JWT_SECRET`、`JWT_EXPIRATION`、`WX_APPID`、`WX_SECRET`、`ACCESS_PREFIX`。本机直连时，`DB_URL` 的主机写 `127.0.0.1`，`REDIS_HOST` 也写 `127.0.0.1`。容器里才写服务名 `mysql` 和 `redis`。

`JWT_SECRET` 给 HS256 用，长度至少 32 字节。`JWT_EXPIRATION` 在代码里被当成毫秒，加到当前时间上。

## 课堂练习

1. 在 IDE 里展开 `modules/user`，把 `controller`、`service`、`mapper`、`entity`、`dto` 五个包各指出一个类，并说它给谁用。
2. 启动 MySQL 和 Redis。确认库 `clock_my_goal` 里有 `user`、`goal`、`goal_label`、`admin_user`。
3. 启动 `Application`。用接口工具调用：

```http
POST http://localhost:9090/auth/register
Content-Type: application/json

{
  "userName": "张三",
  "password": "pass123",
  "sex": 1,
  "age": 18
}
```

成功时响应形如：

```json
{
  "code": 0,
  "message": "操作成功",
  "data": 1
}
```

`data` 是新用户 id。再用同一套用户名密码调用 `POST /auth/login`，响应 `data` 里应有 `token`。

注册校验在 `RegisterDto`：用户名 1 到 10 个字符，允许中文、字母和间隔号；密码 6 到 20 位，允许字母、数字、`_`、`+`、`-`。`AuthController.register` 目前没有 `@Valid`，这些注解要等参数上加了 `@Valid` 才会生效。第 3 课专门讲这件事。如果这节注册被数据库唯一约束拦住，说明用户名已经存在。

## 下课前对一下

- 根 `pom.xml` 管版本和模块列表，`clock-my-goal` 才是可运行的服务。
- 一个业务类的包名就能说明它的层。
- `application.yaml` 写占位，Compose 或本机环境变量给值。
- 表结构的来源是 `docker/mysql/init/init.sql`，而且只在 MySQL 数据目录为空时执行。
- 注册、登录的 HTTP 响应已经是 `{ code, message, data }`。谁包的这一层，第 3 课再打开 `GlobalResponseHandler`。
