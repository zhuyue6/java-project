## 讲解

### 1. 四个容器在同一个网里

`docker-compose.yaml` 定义了网络 `app-net`。同一个网络里的服务用**服务名**当主机名。

| 服务 | 镜像 | 对宿主机暴露 | 在网内被谁访问 |
| --- | --- | --- | --- |
| `mysql` | `mysql:8.0` | `3306` | 应用用 `mysql:3306` |
| `redis` | `redis:7-alpine` | `6379` | 应用用 `redis:6379` |
| `clock-my-goal` | 自己构建的 `clock-my-goal:0.1.1` | `9090` | Nginx 用 `clock-my-goal:9090` |
| `nginx` | `nginx:1.26-alpine` | `80`、`443` | 浏览器访问域名 |

应用的环境变量把第 1 课的占位填上，例如：

- `DB_URL` 的主机是 `mysql`，库名 `clock_my_goal`，时区 `Asia/Shanghai`。
- `REDIS_HOST=redis`。
- `SERVER_PORT=9090`，和 `application.yaml` 的 `${SERVER_PORT:9090}` 对应。
- `JWT_SECRET`、`JWT_EXPIRATION`、`WX_APPID`、`WX_SECRET`、`ACCESS_PREFIX` 同样从这里进入进程。

Java 代码只读 `application.yaml` 里的名字。换数据库地址时改 Compose（或服务器上的环境变量），不用改 `UserMapper`。

`depends_on` 让应用等到 MySQL、Redis 的 healthcheck 通过后再启动。MySQL 的初始化脚本只在数据卷是空的时候执行，第 1 课已经用过。

Redis 开启了 `appendonly`，黑名单和用户状态键会写进数据卷 `redis-data`。登出后重启 Redis 容器，未过期的黑名单仍然在。

### 2. 镜像里有什么

`clock-my-goal/Dockerfile` 分两段：

1. `maven:3.9.9-eclipse-temurin-17` 在 `/workspace` 编译。它先拷贝根 `pom.xml` 和模块源码，再执行 `mvn -pl clock-my-goal -am clean package -DskipTests`。构建上下文是仓库根目录，因为父 POM 在根上。命令形如：

```sh
docker build -f clock-my-goal/Dockerfile -t clock-my-goal:0.1.1 .
```

末尾的 `.` 是仓库根目录。版本号要和 Compose 里的 `image: clock-my-goal:0.1.1` 一致。

2. `eclipse-temurin:17-jre-jammy` 只带走打好的 jar：`/app/app.jar`。运行用户是 `app`，入口是 `java -jar /app/app.jar`。这一层没有 Maven，也没有源码。

容器声明 `EXPOSE 9090`。真正映射到宿主机端口的是 Compose 的 `ports: "9090:9090"`。

### 3. Nginx：静态站和接口前缀

浏览器只访问 80 或 443。Nginx 按路径分成两支，配置在 `server` 里各写了一份（HTTP 与 HTTPS 结构相同）：

```nginx
location / {
    root /usr/share/nginx/html;
    index index.html;
    try_files $uri $uri/ /index.html;
}

location /api/ {
    proxy_pass http://clock-my-goal:9090/;
}
```

`location /` 的根目录来自挂载 `./nginx/html/dist` → `/usr/share/nginx/html`。这是前端打包产物。`try_files` 的顺序是：先找文件，再找目录，都没有则返回 `index.html`。Vue 或 React 的 history 路由因此在刷新时仍能打开页面。

`location /api/` 把请求转到应用容器。`proxy_pass` 的地址以 `/` 结尾时，Nginx 会用这个 URI 替换掉 location 匹配到的前缀 `/api/`。

| 浏览器请求 | 后端收到 |
| --- | --- |
| `GET /api/users/1` | `GET /users/1` |
| `POST /api/auth/login` | `POST /auth/login` |
| `GET /api/goals?keyword=跑步` | `GET /goals?keyword=跑步` |

前端的 axios `baseURL` 写成 `/api`，Controller 的 `@RequestMapping` 从 `/users`、`/goals`、`/auth` 开始。本地绕过 Nginx、直连 `localhost:9090` 时，路径里没有 `/api`。

HTTPS 的证书文件挂在 `./nginx/ssl` → `/etc/nginx/ssl`，配置里的文件名是 `zywyy.crt` 和 `zywyy.key`。申请和安装步骤在仓库根目录 `https.md`，用 acme.sh 写到这组路径，再执行 `nginx -s reload`。这节知道证书是挂进 Nginx 的文件即可。

配置里的跨域头目前是：

```nginx
add_header Access-Control-Allow-Origin *;
add_header Access-Control-Allow-Methods GET,POST,OPTIONS;
```

前后端同域（页面和 `/api` 都在同一个域名下）时，浏览器不发跨域预检，日常请求不受这两行限制。前后端拆到不同源时，`PATCH`、`DELETE` 以及 `Authorization` 头会触发预检，需要在这里补上对应的方法和 `Access-Control-Allow-Headers`。Spring 侧 `WebMvcConfig` 只给 `/admin/**` 配了 `localhost` 的 CORS。排预检失败时，同时看 Nginx 这几行和 `WebMvcConfig.addCorsMappings`。

### 4. 上传文件和日志各看哪一段配置

头像相关的配置键是 `file.accessPrefix`，环境变量名 `ACCESS_PREFIX`。它同时出现在两处：

- `StoreageService.uploadImage` 把文件写到 `./${file.accessPrefix}/images/<uuid>.ext`，方法返回 `images/<uuid>.ext`。类注释里的「`/static/images/...`」和这个返回值不一致，以上面的 `return relativePath` 为准。
- `WebMvcConfig.addResourceHandlers` 用同一个值注册静态资源：URL 模式是 `${file.accessPrefix}/**`，磁盘目录是 `./${file.accessPrefix}/`。

拦截器排除的是路径 `/static/**`。Compose 里 `ACCESS_PREFIX` 当前写成了 `http://localhost:9090`。上课时把这三处放在一起看：配置值、写文件的目录、资源映射的 URL 模式是否是同一段路径。对不上时，图片 URL 打不开，先改配置而不是改 Controller。

日志方面，`application.yaml` 把文件写到 `/var/logs/clock-my-goal/clock-my-goal-app.log`。Compose 把宿主机 `./app/logs/clock-my-goal` 挂到容器的 `/app/logs/clock-my-goal`。两条路径不相同。查容器日志时，先以 yaml 里的 `logging.file.name` 为准，再用 `docker compose logs clock-my-goal` 看标准输出。MyBatis 的 SQL 打在标准输出上。

### 5. 发布顺序

与根目录 `readme.md` 一致，版本号按当次镜像替换：

1. 在仓库根目录构建镜像（见上一节的 `docker build`）。
2. 需要离线拷贝时：`docker save` 导出 tar，拷到服务器后 `docker load`。
3. 把 `clock-my-goal/docker` 目录放到服务器，其中含 `docker-compose.yaml`、`nginx/`、`mysql/init`。
4. 在该目录执行 `docker compose up -d`。
5. `docker compose logs -f mysql` 或 `docker compose ps` 确认四个服务都起来了。

更新应用版本时，同时改镜像标签和 Compose 的 `image` 字段，再重新 `up -d`。MySQL 数据在命名卷 `mysql-data` 里，替换应用容器不会清库。改了 `init.sql` 也不会自动作用到已有卷；改表结构要另写变更脚本。

## 课堂练习

1. 在浏览器里打开前端页面（经 Nginx 的域名或本机 80 端口），对一个会发请求的操作打开网络面板。确认请求 URL 含 `/api`，例如 `/api/auth/login`。
2. 同时看应用日志里的路径。登录应出现对 `/auth/login` 的处理，而不是 `/api/auth/login`。用 `nginx.conf` 里 `proxy_pass` 末尾的 `/` 解释这个差别。
3. 直连 `http://localhost:9090/auth/login` 再发一次相同的 JSON。确认后端路径不带 `/api` 时仍然命中 `AuthController`。
4. 在纸上画出四个方框：浏览器、Nginx、`clock-my-goal`、MySQL/Redis。把第 6 课的登录请求标到这张图上：静态页面来自 Nginx 根目录，`POST /api/auth/login` 被转到 9090，`AuthServiceImpl` 查的是 `mysql`，成功后的后续请求会在 `redis` 查黑名单。

## 下课前对一下

- 容器之间用服务名通信：`mysql`、`redis`、`clock-my-goal`。
- 环境变量填进 `application.yaml` 的占位，业务代码继续读配置名。
- 前端 `baseURL` 为 `/api`；Nginx 去掉这个前缀；Controller 路径从资源名开始。
- history 路由靠 `try_files ... /index.html`。
- 发布是构建镜像、对齐 Compose 里的标签、`docker compose up -d`。数据库在卷里，和这次换上去的 jar 分开。

## 八课之后能独立做的事

拿到一个新需求时，按这条顺序落代码：

1. 定 HTTP 方法和路径（第 2 课的表）。
2. 写 Request / Response，校验放在 Request 上，Controller 参数加 `@Valid`（第 3 课）。
3. 在 Service 里写规则，失败抛 `BusinessException`（第 4 课）。
4. 需要查表时补 Mapper 方法和 XML，动态条件用 `<if>`，用户数据带上 token 里的 userId（第 5、7 课）。
5. 接口需要登录就不加 `@IgnoreJwt`；不要从 body 里取 userId（第 6 课）。
6. 用直连 `9090` 的路径自测，再用带 `/api` 的路径对一次 Nginx（第 8 课）。
