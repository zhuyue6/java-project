## 讲解

### 1. 三种对象，三套字段

前端习惯一个 TypeScript interface 走完全程。这个项目把「线上来的」「表里的」「返回去的」拆开。

**Request，HTTP 入参。** 只放客户端应该提交的字段，校验注解写在这里。

`UserListRequest` 是列表查询：

```10:22:clock-my-goal/src/main/java/com/zhuyue/clockMyGoal/modules/user/dto/request/UserListRequest.java
public class UserListRequest {
  @Pattern(regexp = "^[a-zA-Z0-9._]*$", message = "关键词只能包含字母、数字、下划线、点")
  private String keyword;

  @Min(value = 0, message = "状态必须为0或1")
  @Max(value = 1, message = "状态必须为0或1")
  private Integer status;

  @NotNull(message = "页码不能为空")
  private Integer pageNum;
  @NotNull(message = "每页条数不能为空")
  private Integer pageSize;
}
```

`keyword` 和 `status` 可以缺省。`pageNum`、`pageSize` 用的是 `Integer`，缺了就是 `null`，`@NotNull` 能拦住。如果字段类型写成原始类型 `int`，缺省会变成 `0`，`@NotNull` 不起作用。

**Entity，和表对应。** `User` 含 `password`、`status`、`LocalDateTime createTime`。它给 MyBatis 填行、读行，响应里出现密码是把实体直接返回了。

**Response，给前端的视图。** `UserResponse` 有 id、用户名、年龄、性别、头像、状态，以及已经格式化成字符串的 `createTime`、`updateTime`。没有 `password`。

`LoginResponse` 继承 `UserResponse`，多一个 `token`。登录接口因此能同时给令牌和资料，序列化结果是一个扁平对象，token 和用户字段在同一层。

`PageResponse<T>` 是列表信封：`pageNum`、`pageSize`、`total`、`data`。它仍然是业务返回值，外面还会再被 `ApiResponse` 包一次。

时间在这个项目里有两种形态：

- 请求进服务、写数据库时用 `LocalDateTime`。`CreateGoalRequest.expirationTime` 用 `@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")` 解析字符串。
- 响应出服务时用字符串。`UserServiceImpl.convertToUserResponse` 调用 `TimeService.getTimeStringByTime`，格式同样是 `yyyy-MM-dd HH:mm:ss`。

前端提交时间和展示时间可以用同一套格式。

### 2. 校验什么时候才会执行

注解写在字段上只是声明。触发校验的是 Controller 参数上的 `@Valid`（或类上的 `@Validated` 配合方法参数上的约束）。

三类绑定，失败时抛出的异常不同，最后都被收成同一个错误码：

| 绑定方式 | 典型接口 | 校验失败的异常 |
| --- | --- | --- |
| `@RequestBody` + `@Valid` | `POST /goals` | `MethodArgumentNotValidException` |
| `@ModelAttribute` + `@Valid` | `GET /users` | `BindException` |
| JSON 解析失败、body 为空、Content-Type 不对 | 任意 `@RequestBody` | `HttpMessageNotReadableException` |

`GoalController` 类上有 `@Validated`，`createGoal` 的 body 上还有 `@Valid`，所以 `CreateGoalRequest` 的 `@NotNull`、`@Min`、`@Max` 会执行。打卡周期只允许 1、2、3。

`UserController.getUserList` 使用 `@Valid @ModelAttribute`，query 不合法时走 `BindException`。

`AuthController.login` 和 `register` 的参数目前只有 `@RequestBody`，没有 `@Valid`。`LoginDto`、`RegisterDto` 上的 `@NotBlank`、`@Size`、`@Pattern` 因此不会在进入方法前执行。用户名密码的业务判断在 `AuthServiceImpl` 里，用的是另一套错误码（用户不存在、密码错误）。第 4 课会看到那段代码。

给登录补上校验，就是在参数前加上 `@Valid`，DTO 上的文案会原样出现在响应 `message` 里。

### 3. 成功响应谁包的

Controller 返回 `UserResponse` 或 `long` 或 `void`。浏览器收到的是 `ApiResponse`：

```12:17:clock-my-goal/src/main/java/com/zhuyue/clockMyGoal/common/util/ApiResponse.java
  public static <T> ApiResponse<T> success(T data) {
    ApiResponse<T> result = new ApiResponse<>();
    result.code = 0;
    result.message = "操作成功";
    result.data = data;
    return result;
  }
```

`GlobalResponseHandler` 实现了 `ResponseBodyAdvice`。Controller 方法正常返回后、写成 HTTP 体之前，会进 `beforeBodyWrite`：

- 方法或类上有 `@IgnoreApiResponse`：原样输出。
- 返回值类型已经是 `ApiResponse`：不再包一层。异常处理器返回的就是 `ApiResponse`，这里要避开，否则失败会被再包成 `code: 0`。
- 其他情况：`ApiResponse.success(body)`。
- 方法签名返回 `String` 时，Spring 已经选了字符串转换器。这时把对象手动序列化成 JSON 字符串，并把 `Content-Type` 设为 `application/json`。

所以业务代码里再 `return ApiResponse.success(...)` 有两种结果：要么被 `supports` 当成「已经是 ApiResponse」直接放过，要么在运行时再次被判断。现行写法是 Controller 返回业务对象，包装交给这一个类。

`void` 方法的 body 是 `null`，成功响应为：

```json
{ "code": 0, "message": "操作成功", "data": null }
```

前端把「删掉了」「更新了」看成 `code === 0`，`data` 为空是预期。

### 4. 失败也走同一套形状

业务代码抛 `BusinessException`。它可以接收一个 `ExceptionCodeEnum`：

```java
throw new BusinessException(ExceptionCodeEnum.UserNotFound);
```

`GlobalExceptionHandler` 上每个 `@ExceptionHandler` 负责一种异常，方法返回值同样是 `ApiResponse`：

| 异常 | 响应 |
| --- | --- |
| `BusinessException` | `code`、`message` 来自异常本身 |
| `MethodArgumentNotValidException` | `code = 10006`，`message` 取第一个字段错误文案 |
| `BindException` | 同上，用于 GET query |
| `HttpMessageNotReadableException` | `code = 10006`，`message` 为「参数错误」 |
| 其他 `Exception` | `code = 10001`，`message` 为异常信息 |

字段校验的 `message` 就是注解里写的那句中文，例如「页码不能为空」「打卡周期不能小于1」。前端可以把 `message` 直接展示。

错误码分段，方便前端做统一拦截：

| 区间 | 含义 | 例子 |
| --- | --- | --- |
| `0` | 成功 | `ApiResponse.success` |
| `10001`–`10006` | 系统级 | 10004 未登录，10005 登录过期，10006 参数错误 |
| `11xxx` | 用户 | 11001 用户不存在，11002 用户名或密码错误，11004 账号停用 |
| `12xxx` | 文件 | 12001 类型不对，12002 上传失败 |
| `13xxx` | 标签 | 13001 同分类下名称已存在，13002 标签不存在 |
| `14xxx` | 目标 | 14001 目标不存在 |
| `15xxx` | 管理员 | 15002 管理员用户名或密码错误，15004 管理员停用 |

前端响应拦截器建议：

- `code === 0`：把 `data` 交给页面。
- `code === 10004` 或 `10005`：清本地 token，跳登录。
- `code === 10006`：展示 `message`，留在表单页。
- `11xxx` 及以上：展示 `message`，按业务决定是否回退。

拦截器在未登录时还会把 HTTP 状态设为 401，同时抛 `BusinessException`。前端若只看 HTTP 状态，401 表示要重新登录；若走统一 JSON，则看 `code`。两套信号在这个项目里会同时出现，拦截器以 `code` 为准更稳，因为参数错误、业务错误多数仍然是 HTTP 200 加业务 `code`。讲第 6 课时可以让大家在网络面板里对一次 401 看响应体。

### 5. 和 axios 拦截器的对应关系

```text
请求发出
  → 后端 GlobalAuthInterceptor     相当于请求拦截器里检查 token 的那一端
  → Controller / Service
  → 正常：GlobalResponseHandler    相当于响应拦截器看到的成功包
  → 异常：GlobalExceptionHandler    相当于响应拦截器看到的失败包
```

后端已经把分页、详情、报错收成同一种 JSON。前端拦截器只解析一次，页面拿 `data` 或错误文案。

## 课堂练习

服务已按第 1 课启动。逐个发下面的请求，记录 `code` 和 `message`。

1. `GET /users`，不带 `pageNum`、`pageSize`。预期 `code` 为 10006，`message` 来自 `UserListRequest` 上的 `@NotNull`。
2. `GET /users?pageNum=1&pageSize=10&keyword=张三!`。`keyword` 的正则不允许中文和感叹号，预期仍是 10006，文案是「关键词只能包含字母、数字、下划线、点」。
3. `POST /goals`，先不带 token。预期未授权。带上第 1 课登录得到的 token 后，body 里不写 `expirationTime`。预期 10006，「过期时间不能为空」。
4. `POST /goals`，`expirationTime` 写成 `2026/12/31`。这进不了字段校验，JSON 无法按 `yyyy-MM-dd HH:mm:ss` 转成时间，预期仍是 10006，「参数错误」。
5. `POST /auth/login`，body 为 `{}`。观察结果，并打开 `AuthController.login` 确认参数上有没有 `@Valid`。把现象和 `POST /goals` 缺字段的现象放在一起讲：注解在 DTO 上，是否执行取决于参数注解。

再打开 `User` 和 `UserResponse`，列出只存在于实体、不会出现在用户详情响应里的字段。预期至少有 `password`。

## 下课前对一下

- Request 接外部输入，Entity 对齐表，Response 给前端。密码留在实体和登录用的内部对象里。
- `@Valid` 写在 Controller 参数上，校验文案写在 DTO 字段上。
- 成功 `code` 为 0，包装类是 `GlobalResponseHandler`。
- 失败同样是 `ApiResponse`，业务码来自 `ExceptionCodeEnum`，参数问题统一 10006。
- 分页列表的数组在 `response.data.data`。
