## 什么是jwt, 为什么需要jwt？
json web token 是一段经过签名的字符串，服务端可以通过校验签名，确认这段信息是自己签发的、没有被篡改过，从而信任其中携带的用户身份信息。

#### 优点

1. **无状态易扩展**：服务端不需要存储会话，非常适合分布式集群、微服务架构，水平扩展无压力。
2. **跨域友好**：不受 Cookie 同源策略限制，轻松实现跨系统认证、单点登录。
3. **信息自包含**：可携带基础用户信息，减少服务端数据库查询次数。
4. **语言无关**：基于标准 JSON，Java、Go、Node.js 等所有开发语言都支持。

#### 缺点

1. **无法主动吊销**：令牌一旦签发，在过期前始终有效，无法提前作废；用户登出、修改密码时，旧令牌依然可用，需额外实现黑名单机制。
2. **Payload 不安全**：Base64 编码可逆，不能存放敏感数据。
3. **续期成本高**：过期时间太短用户体验差，太长不安全；通常需要搭配 Refresh Token 实现无感续期，增加架构复杂度。
4. **体积开销**：比 SessionID 大很多，携带信息越多，请求网络开销越大。


## 组成部分

### Header 
- typ: 令牌类型，固定是JWT
- alg: 签名的算法：
  - 对称加密HS256
  - 非对称加密RS256

### Payload
- `iss` (issuer)：令牌签发者
- `exp` (expiration time)：过期时间，Unix 时间戳格式
- `sub` (subject)：主题，通常是用户唯一标识
- `aud` (audience)：令牌受众
- `iat` (issued at)：签发时间
- `nbf` (not before)：生效时间

通常使用 exp 与 sub 

### Signature

签名是 JWT 的安全保障，用于验证数据完整性和签发者身份，生成规则：

1. 取出编码后的 Header 和编码后的 Payload，拼接成 `header.payload`
2. 使用 Header 中指定的签名算法，加上**密钥（secret）** 对拼接后的字符串进行签名
3. 生成的签名结果作为 JWT 的第三部分
