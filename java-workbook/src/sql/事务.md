# 什么是事务？

**事务是一组 SQL 操作，这组 SQL 要么全部成功执行，要么全部失败回滚，不会出现只做一半的情况**。
spring 中使用 @Transactional 注解来开启事务，不要写到mapper里面


# 事务特点
ACID
MySQL 默认自动提交（autocommit=1）：每一条 SQL 单独就是一个事务，执行完自动 commit。

## 原子性 automatic
事务是不可拆分的最小单元，全部成功、或者全部失败，不存在"一半"

```sql
   -- a 给 b 转账 100
   -- a账号 - 100
   update account set money = money - 100 where name='a';
   -- b账号 + 100
   update account set money = money + 100 where name='b';

```
如果第一条执行成功，第二条数据库宕机、报错：
- 没有事务：A 钱扣了，B 没加上 → 数据错乱
- 包在事务里：第一条自动回滚，A 余额恢复原样，不会只扣钱

```sql
  begin;
  update account set money = money - 100 where name='a';
  update account set money = money + 100 where name='b';
  commit;
```

## 一致性 consistency
事务执行前后，数据满足业务约束，从一个合法状态变成另一个合法状态，不会出现非法中间状态。
- 约束：转账前后，A+B 总金额不变
- 事务成功：A 少 100，B 多 100，总和不变 ✅
- 事务失败：回到转账前状态，总和不变 ✅
如果没有事务，只扣不加，总和变少，破坏一致性

## 隔离性 Isolation
多个事务并发跑的时候，互相之间要隔离，**一个事务看不到另一个事务不合理的中间状态**。
隔离不是完全隔绝，隔离级别决定隔离程度，也就是前面说的脏读、不可重复读、幻读的来源。
四个隔离级别：

1. RU 读未提交：能读到别人没提交的数据（脏读）
2. RC 读已提交：只能读到别人提交完的数据；会有不可重复读、幻读
3. RR 可重复读（MySQL InnoDB 默认）：同一个事务内多次读同一快照，解决脏读、不可重复读；依靠 MVCC + 间隙锁处理幻读
4. Serializable 串行化：事务串行执行，完全隔离，无并发问题，性能最差

## 持久性 Durability
事务一旦 `commit` 提交成功，修改就永久写入磁盘，就算数据库宕机、断电，数据也不会丢。
靠 redo log（重做日志）实现：提交前先写 redo log，再刷数据页。宕机重启，根据 redo log 恢复已经提交的事务。
